# GridPulse — Electricity Demand Spike Alert (Team 11)

A Streamlit application that estimates whether the next hour's electricity demand may exceed a rolling demand threshold.

## What changed in this updated package

- Dataset expanded to **8,760 hourly records** (more than the team-leader target of 5,000).
- The prediction screen now asks for simple values: **hour, day of week, temperature, humidity and current demand**.
- Previous-hour demand is derived from the latest dataset record; users no longer enter rolling mean or rolling standard deviation.
- The live prediction recalculates when an input changes.
- A temperature-sensitivity graph updates for the current humidity, demand, hour and day of week, making risk changes visible.
- Training uses seven meaningful predictors, a baseline and two different ML algorithms. The app derives weekend status and previous-hour demand automatically, so users do not need to enter technical lag values.
- Chronological train/validation/test split is 70% / 10% / 20%; the test period remains untouched during threshold selection.
- Includes confusion matrix, class metrics, two error slices and misclassified test examples.
- Model and preprocessing pipeline are saved together in `models/best_model.joblib`.

## Dataset notice — read this before submission

The included 8,760-row dataset is **synthetic educational demonstration data**, generated by `data/generate_dataset.py` with fixed seed 42. It is not real electricity-board or utility data. The project is suitable for demonstrating a reproducible ML workflow, but do not describe the data as real measurements. Confirm with your mentor that synthetic data is acceptable for your chosen project. If real-world data is required, replace the CSV with a legally usable, mentor-approved source and document its source, licence, collection period and limitations.

Target definition: `spike_next_hour = 1` when the next hour's demand is greater than 110% of the previous 24-hour mean; otherwise it is `0`.

## Run in VS Code

1. Extract the ZIP file.
2. Open the extracted `GridPulse_Team11_VSCode` folder in VS Code.
3. Open Terminal → New Terminal.
4. Create a virtual environment:

   ```bash
   python -m venv .venv
   ```

5. Activate it:

   **Windows PowerShell**
   ```powershell
   .venv\Scripts\Activate.ps1
   ```

   **Windows CMD**
   ```cmd
   .venv\Scripts\activate.bat
   ```

6. Install dependencies:

   ```bash
   pip install -r requirements.txt
   ```

7. (Optional) Regenerate the included dataset:

   ```bash
   python data/generate_dataset.py
   ```

8. Train and save the model:

   ```bash
   python train_model.py
   ```

9. Start the app:

   ```bash
   streamlit run app.py
   ```

## Reproducibility

- Fixed random seed: 42.
- Dataset generator: `python data/generate_dataset.py`.
- Training command: `python train_model.py`.
- Saved model includes its fitted preprocessing/model pipeline and selected decision threshold.
- Dataset version: synthetic 2025 hourly series, 8,760 rows.

## Limitations

- Synthetic patterns may be easier to predict than real electricity demand.
- The output is a classroom prototype, not an operational grid forecast or safety system.
- A model alert is a probability-based estimate; changing an input may change the probability without necessarily crossing the final alert threshold.
